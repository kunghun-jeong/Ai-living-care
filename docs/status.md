## 안전 — 담당자 통지 (⚠ 미해소 · D-18)

**이 표가 소유 경계를 넘는 유일한 통로다.** 결함은 담당자 코드에 있고 생태계 담당은 고치지
않는다(D-17). 대신 여기 적고 **귀속 컴포넌트 `CLAUDE.md` 의 `상태` 줄에 같은 ID 를 박는다.**
`make status` 가 그 줄을 매번 수확하므로 결함이 이 문서 안에서 조용히 늙지 않는다.
`anchor.py` A5 가 두 자리의 짝을 **양방향으로** 강제한다 — 표에서 행을 지워도, `상태` 줄에서
지워도 커밋이 막힌다. 지우려면 두 곳을 같이 지워야 하고, 그건 「해소했다」는 선언이다.

| ID | 귀속 (`상태` 줄에 박힌 곳) | 결함 | 영향 |
|---|---|---|---|
| **F-1** | `worker_ai_agent/perception` | 카메라 `msg.encoding` 무검증 `reshape` → 콜백 예외 → `rclpy.spin` 스레드 사망 | 카메라뿐 아니라 **Nav2 액션 콜백까지 전부 정지**. MCP 클라이언트에는 에러가 안 간다 |
| **F-2** | `worker_ai_agent/action` | goal 수락 5초 타임아웃 후 **goal을 취소하지 않는다** | Nav2는 수락했으므로 **로봇은 달리는데 핸들이 없어 `cancel()`로 못 멈춘다.** RTF 0.04에서 상시 발생 |
| **F-3** | `worker_ai_agent/perception` | 프레임 신선도 검사 없음 | 카메라가 죽어도 옛 사진으로 **"할머니 정상"을 계속 보고한다** |
| **F-48** | `worker_ai_agent/action` | 120초 완주 타임아웃도 goal 을 취소하지 않는다 (F-2 의 5초 수락 타임아웃과 별개) | 로봇은 달리는데 시퀀스는 종료, 나중에 `succeeded`로 덮인다 |
| **F-51** | `worker_ai_agent/reasoning` | **죽은 카메라가 「사람 없음 확정」이 된다** (`Reasonings.py:129`) — F-3 의 반대축(미탐) | `status()`에 「새 프레임 없음」 필드가 없어 **미검출과 무관측을 구분할 수 없다** |

> 다섯 건은 하네스가 「안전 경로」로 지정한 축과 정확히 겹친다 — **로봇 정지·취소**(F-2·F-48) ·
> **사람 검출→판정**(F-51) · **프레임 신선도**(F-1·F-3). 그래서 실행 차단(F-4~F-10)과 분리해 둔다.
> F-48·F-51 은 아래 「미해소 — 코드」에 있던 것을 이 축으로 옮긴 것이다 (중복 아님).

**담당자가 해소하는 절차** — 셋을 한 PR 에서 함께 한다:

1. 코드를 고친다. 이 트리는 담당자 소유이므로 별도 승인이 없다.
2. **실패 경로를 한 번 실행하고 출력을 PR 에 붙인다.** 안전 결함은 「고쳤다」로 닫지 않는다.
3. 이 표의 행과 컴포넌트 `상태` 줄의 ID 를 **함께 지우고** 아래 표에 한 줄 남긴다.

## 결함 이력

**F-1 ~ F-63 전문은 [`docs/status-defects.md`](status-defects.md) 에 있다.** 여기서 뺀 이유는
이 문서가 **매 세션 자동 로딩**되기 때문이다 — 결함은 계속 늘어나는데, 늘어난다고 해서
모든 세션이 그 이력을 읽을 이유는 없다. **결함을 기록하는 일이 예산에 막히면 안 된다.**

여기 남는 것은 **지금 작업에 영향을 주는 것**뿐이다: 위 안전 표 · 크리티컬 갭 `G-1`~`G-6` ·
착수 전 확인 `U-*`. 나머지(해소 이력, 규범 결정 불능, 실행 차단, 정본 갈라짐, 포렌식 원문)는
결함 문서에 있고 **`F-` 번호로 찾는다.**
