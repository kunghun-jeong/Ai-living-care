## A. 코드 결함

### A-1 [CRITICAL] 카메라 콜백의 무검증 reshape 하나가 ROS 노드 전체를 조용히 죽인다

`Perceptions.py` — `msg.encoding`을 한 번도 읽지 않고 `reshape(h, w, 3)`한다.
`rgba8`·`mono8`·`16UC1`(depth)·행 패딩 프레임이 한 장이라도 들어오면 `ValueError`.

rclpy는 콜백 예외를 재전파하므로 → `rclpy.spin()`이 탈출 → **데몬 스레드 사망** →
**카메라뿐 아니라 ActionClient의 goal-response/result 콜백도 영원히 오지 않는다.**
MCP 클라이언트에는 아무 에러도 안 가고 stderr 트레이스백만 남는다.

현실적 트리거: URDF에 `depth_camera_link`가 있고 실물 LIMO는 RealSense다.

### A-2 [CRITICAL] `navigate_waypoints`는 입력 검증이 0이다

`waypoints: list` bare 어노테이션 → JSON 스키마 `{"type":"array","items":{}}` (pydantic 실측 확인).
LLM이 자연스럽게 보내는 `[{"x": 1, "y": 0}]`의 **정수**가 그대로 통과해
`pose.pose.position.x = x`에서 rosidl의 `assert isinstance(value, float)`가 터진다.
이 예외는 `try/except`가 없는 데몬 스레드 안이라 **스레드 즉사**.

결과: `sequence_result`는 영원히 `None`, `is_running_sequence()`는 `False`.
Manager LLM은 `get_status`를 폴링하며 **영원히 완료를 기다린다.**

### A-3 [CRITICAL·안전] 5초 수락 타임아웃이 "핸들 없이 달리는 로봇"을 만든다

`accepted_event.wait(timeout=5.0)` 실패 시 반환만 하고 **goal을 취소하지 않는다.**
이후 Nav2가 수락 응답을 보내면 핸들은 로컬 변수에 담긴 채 버려지고, **로봇은 실제로 주행을 시작한다.**

이때 `self._goal_handle is None`이므로 `cancel()` tool은 `{"cancelled": false, "reason": "no active goal"}`.
**MCP 인터페이스로 로봇을 정지시킬 방법이 없다.** RTF 0.04~0.06 환경에서는 예외가 아니라 **상시 발생 경로**다.

### A-4 [CRITICAL] 프레임 신선도 검사가 어디에도 없다

`_latest`는 한 번 채워지면 만료되지 않는다. `stamp`를 반환하지만 **누구도 `now - stamp`를 비교하지 않는다.**

Gazebo가 죽든 카메라가 빠지든 `detect_objects`는 10분 전 프레임에서 사람을 검출하고,
Manager는 **"할머니 거실에 계심 · 정상"** 으로 판정한다. **돌봄 로봇에서 가장 위험한 무음 실패다.**

### A-5 [HIGH] stale action 콜백이 새 goal의 상태를 덮어쓴다 (G-5의 구체 경로)

`_on_result`/`_on_feedback`에 goal_id 대조가 없다.

- **(a)** `cancel_goal()` → 새 시퀀스 시작 → 구 goal의 `_on_result`가 도착해
  `_goal_handle = None`(새 핸들 파괴) + `status = "failed"` → 새 목표는 취소 불가 + 시퀀스 즉시 중단
- **(b)** `_on_result`가 `"succeeded"`를 쓴 뒤 큐에 남은 feedback이 `"navigating"`으로 되돌림 →
  120초 타임아웃까지 돌고 **성공한 웨이포인트를 실패로 보고**

`status`/`last_goal`/`_goal_handle`을 **3개 스레드가 락 없이 공유**한다.

### A-6 [HIGH] 120초 타임아웃이 벽시계인데 로봇은 sim time에 산다

RTF 0.04~0.06에서 120초 벽시계 = sim 5~7초 ≈ **1.3 m 주행분**.
첫 웨이포인트에서 반드시 타임아웃 → 시퀀스 중단. **한편 로봇은 계속 달린다**(타임아웃 경로에 `cancel_goal()` 없음).
A-3과 결합해 "보고상 정지 / 실제 주행" 상태가 만들어진다.

`LimoGatewayNode`는 `use_sim_time`을 설정하지 않아 노드 클럭은 벽시계, 프레임 stamp는 sim time —
**한 모듈 안에 두 시간축이 섞여 있다.**

### A-7 [HIGH] YOLO 모델을 여러 스레드가 동시 호출 + 전역 초기화 레이스

`yolo_detect` 호출 경로 3개가 전부 다른 스레드인데 `if _yolo_model is None` 구간에 락이 없다.
가중치 이중 다운로드/이중 로딩 가능. ultralytics 모델 객체는 동시 `predict`에 안전하지 않다.

### A-8 [HIGH] 사람검출 → 증거이미지 체인이 구조적으로 끊겨 있다

`PersonScan`이 남기는 `hit["bbox"]`를 **`crop_fn`에 넘기는 코드가 저장소 어디에도 없다.**
증거 이미지를 만드는 유일한 함수 `check_object_state`는 **hit 프레임이 아니라 "지금 최신 프레임"에서
YOLO를 다시 돌린다.** `frame_id`를 넘기면 1프레임만 지나도 `None`, 안 넘기면 다른 사진이 증거가 된다.

**시나리오 1의 핵심 산출물이 구조적으로 생성 불가능하다.**

### A-9 [HIGH] `send_goal.py`의 폴링 루프가 실패 시 영원히 안 끝난다

`status` 6종 중 탈출 조건은 `succeeded`/`failed` **2종만** 검사한다.
Nav2 미기동(`idle`) · goal 거부(`rejected`) · 120초 초과(`navigating` 유지) → **무한 루프, 에러 한 줄 없이.**
전체 타임아웃도 없다.

### A-10 [HIGH] patrol_viz는 로봇을 절대 못 그린다

TF는 `map → base_footprint`를 발행하는데 URDF에서 `base_footprint` 링크와 `base_joint`가
**주석 처리돼 있다.** URDF 루트는 `base_link`이고 `map → base_link` 변환은 아무도 발행하지 않는다.
RViz RobotModel은 `No transform` 으로 실패 → **이 도구의 존재 이유가 정면으로 깨진다.**

`WHEELS` 리스트 앞 두 개는 turtlebot3 조인트명이라 URDF에 없다.

### A-11 [HIGH] ThreadPoolExecutor — 타임아웃이 작업을 취소하지 않고, 큐가 무한 증가하며, 종료도 안 한다

`future.cancel()` 없음 · 큐 상한 없음 · `shutdown()` 없음.
워커 2개가 막히면 이후 모든 호출이 타임아웃을 반환하는 **영구 고착**이 된다.
`except FutureTimeoutError`만 잡아 ultralytics `ImportError`·CUDA 에러가 dict 계약을 뚫는다.

## C. 실행 가능성

### C-1 [HIGH] `mcp[cli]` 하한 없음 — 코드는 9일 전 릴리스된 2.0에서만 동작한다

**실물 휠 검증**:

| SDK | `mcp.server.mcpserver` | `mcp.server.fastmcp` |
|---|---|---|
| **2.0.0** (현재 최신) | ✅ | ❌ 삭제됨 |
| 1.29.0 이하 전부 | ❌ **없음** | ✅ |

`requirements.txt`에 `mcp>=2.0` 하한조차 없다. 락파일·캐시·사내 인덱스로 1.x가 잡히면
서버가 import 단계에서 죽고, 클라이언트는 자식 프로세스 사망을 만나 불투명하게 실패한다.

**mcp 2.0은 `Requires-Python >=3.10`** → 실물 LIMO의 ROS2 Foxy(Python 3.8)에서는 **설치 자체가 불가**하다.

> **U-1의 "반대 증거"는 틀렸다.** 실물 왕복으로 반증했다 — `session.initialize()`는 2.0에서
> **제거되지 않았다.** 이 import는 최신 SDK의 정확한 신 API가 맞다.
> 조치는 "버전 확인"이 아니라 **`mcp[cli]>=2.0,<3` 하한 고정**이다.

### C-2 [HIGH] 의존성 선언 누락

| 모듈 | import 위치 | 상태 |
|---|---|---|
| `numpy` | `MCP_server.py`, `Perceptions.py`, `patrol_*.py` | ❌ 미선언 — `ultralytics` 전이 의존에 얹힘 |
| `cv2` | `patrol_sim.py`, `patrol_viz.py` | ❌ 미선언 |
| `PIL` | `MCP_server.py` `_encode_jpeg` | ❌ 미선언 |
| `tf2_ros` | `patrol_viz.py` | ❌ apt 목록에 없음 |
| `xacro` | `make_urdf.sh` | ❌ 어디에도 없음 |
| `numpy==1.26.4` 핀 | 문서가 "필수"라고 명시 | ❌ requirements에 없음 |

**루트에 `requirements.txt`가 없다** (`SOT.md` §2 구조도는 있다고 그린다).
`tools/limo-patrol-viz/`에도 없어서, "YOLO 필요 없음"이라던 경량 도구가 결국 torch 2.5GB를 요구하게 된다.

### C-3 [HIGH] `.gitattributes`가 `main`에 없다

Windows/OneDrive 체크아웃에서 `.sh` 4종이 CRLF로 떨어지면
`bash: /bin/bash^M: bad interpreter`. 실행 비트도 유실돼 `Permission denied`.
**문서화된 모든 `./*.sh` 명령이 Windows 경유 클론에서 실패한다.**

### C-4 [HIGH] venv 사용 시 `rclpy` 미가시 — 미문서·치명적

`rclpy`는 apt로 `/usr/lib/python3/dist-packages`에 있어 순수 venv에서 안 보인다.
`Scenarios/*.py`가 `command="python3"`로 서버를 띄우므로 venv가 활성이면 자식도 venv python →
`ModuleNotFoundError: rclpy`. **`--system-site-packages`가 필수인데 어디에도 없다.**

### C-5 [MEDIUM] `map.yaml`을 아무도 읽지 않는다

`resolution`·`origin`·임계값이 담겨 있으나 **코드 어디서도 파싱되지 않는다.**
같은 값이 `patrol_sim.py`·`patrol_viz.py`에 하드코딩돼 있고, 임계값은 아예 다르다
(yaml `occupied_thresh 0.65` vs 코드 `img > 250`).
**맵을 교체하면 yaml만 갱신되고 코드는 조용히 옛 원점으로 계산한다.**

같은 `map.pgm`을 **두 개의 다른 파서**가 읽는다 (`cv2.imdecode` vs 자체 `read_pgm`).

### C-6 [MEDIUM] `map.pgm`이 어떤 자산 표에도 없다

두 순찰 도구의 **모듈 로드 시점 하드 의존**인데 README 자산 표에는 AWS 메시와 `yolov8n.pt`만 있다.
없으면 `FileNotFoundError`로 즉사한다.

### C-7 [MEDIUM] LLM 코드가 0줄인데 README 다이어그램은 있는 것처럼 읽힌다

Ollama·OpenAI·Anthropic·`localhost:11434` 참조가 저장소 전체에 없다.
문서 계층은 정직한데(`구현 상태: 없음`) README 다이어그램만 최종 시스템을 현재형으로 그린다.

### C-8 확인된 비-리스크

- Python 12파일 전부 `ast.parse` 통과, 셸 4개 전부 `bash -n` 통과
- **코드의 경로 해석은 건전하다.** 전부 파일 기준 상대경로라 통째로 옮겨도 동작한다
  (`MCP_server.py`만 `abspath` 누락, 현재는 우연히 동작)
- `run_coverage.sh` → `patrol_sim.py`는 **실제로 완주한다.** 런타임 하드 의존은 `cv2`+`numpy` 둘뿐
- `ClientSession`의 read timeout 기본값이 `None`이라 서버 기동 20초 지연도 핸드셰이크를 안 깬다
- `Reasonings.py`는 **하네스 없이 즉시 단위 테스트가 된다** (전 경로 실행 확인)
- MCP 왕복 스모크 테스트는 `rclpy` 스텁만으로 ROS2 없이 가능하다 —
  **이 하나가 C-1의 SDK 리스크를 CI에서 영구히 잡는다**

## D. 평가 방법론

### D-1 순찰 시뮬레이션의 "발견 성공"은 자기충족적이다

사람 `PERSON=(-7.5, 0.30)`은 웨이포인트 `(-7.77, 0.56)`에서 **0.38 m** 거리다.
그리고 그 웨이포인트는 코드 주석이 밝히듯 **사각지대를 메우려고 나중에 추가한 점**이다.
발견 판정도 YOLO가 아니라 `abs(da) < CAM_FOV/2 and pd < CAM_RANGE` 기하 조건이고,
**수직 FOV는 모델에 아예 없다** — 쓰러진 사람이 정확히 이 사각이다.

**"93.6% 커버리지 · 사각지대 0"을 논문에 인용하려면** 최소한
(a) 사람을 웨이포인트에서 먼 무작위 위치 N곳에 두고 (b) 수직 FOV를 넣고 (c) 누운 자세를 모델링한
스윕이 필요하다.
