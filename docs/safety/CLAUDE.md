# 안전 결함 — 담당자 통지 (D-18)

> **역할** 소유 경계(D-17)를 넘는 **유일한 통로.** 미해소 안전 결함 하나 = 파일 하나
> **상태** ⚠ 미해소 5건 — `make status` 맨 위에 뜬다
> **읽을 절** 없음 — 절차는 `docs/status.md` 「안전 — 담당자 통지」 (매 세션 자동 로딩)
> **정본** 이 디렉터리. `SOT.md` §6 `D-18` 이 규범

## 여는 법

결함 하나에 파일 하나. **다른 파일은 건드리지 않는다** — 그래서 담당자 둘이 각각
결함을 올려도 충돌하지 않는다 (표에 행을 끼워 넣던 방식은 충돌했다).

```
docs/safety/F-70-nav2-goal-leak.md
```

```markdown
# F-70 · 한 줄 제목

> **귀속** `worker_ai_agent/action`
> **상태** ⚠ 미해소 — 소유 경계(D-17)로 생태계 담당은 고치지 않는다

**결함** 무엇이 잘못됐나
**영향** 그래서 무슨 일이 벌어지나
```

`# F-NN · 제목` 과 `> **귀속** \`경로\`` **두 줄을 `anchor.py` A5 가 읽는다.**
그리고 **귀속 컴포넌트 `CLAUDE.md` 의 `상태` 줄에 같은 ID 를 박는다** — A5 가 두 자리의
짝을 **양방향으로** 강제하므로 한쪽만 지우면 커밋이 막힌다.

`F-` 번호는 `docs/status-defects.md` 의 마지막 번호 다음을 쓴다. 둘이 같은 번호를
집으면 `A10` 이 알려준다 (막지는 않는다).

## 닫는 법

셋을 한 PR 에서 함께 한다.

1. 코드를 고친다. 담당자 트리이므로 별도 승인이 없다.
2. **실패 경로를 한 번 실행하고 출력을 PR 에 붙인다.** 「고쳤다」로 닫지 않는다.
3. **이 파일과 `상태` 줄 ID 를 함께 지우고**, `docs/status.md` 「해소된 안전 결함」에 한 줄.

## 왜 여기가 자동 로딩이 아닌가

`docs/status.md` 는 매 세션 열리고 거기에 **D-18 절차**가 남아 있다. 목록까지 거기 두면
결함이 늘 때마다 자동 로딩 예산이 늘고 — **결함을 기록하는 일이 예산에 막히면 안 된다**
(2026-08-07 에 `status-defects.md` 를 분리한 것과 같은 이유).

**존재 신호는 이미 두 경로로 간다:** `make status` 맨 위 목록과, 귀속 컴포넌트
`CLAUDE.md` 의 `상태` 줄. 그 컴포넌트를 건드리는 사람은 하네스 §1 에 따라 그 문서를
먼저 읽는다 — 결함이 필요한 사람에게 도달하는 경로는 그쪽이다.
