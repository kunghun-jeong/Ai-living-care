# 설계 정본 (spec v0.2)

> **역할** 계층·인터페이스·정책 연속체의 설계 정본. **통독하지 않는다 — 지목된 절만 연다**
> **상태** v0.2 · 결정 `D-1`~`D-18` 반영
> **읽을 절** 각 컴포넌트 `CLAUDE.md` 헤더가 지목한 절만. 이 문서는 그 **지도**다
> **정본** 설계는 여기 · 구조는 `SOT.md` · 상태는 `docs/status.md`

## 절 색인 — 읽는 시점에 만든다

**색인을 파일에 두지 않는다.** 줄 번호와 절 크기는 spec 이 정본인 **파생 데이터**라,
spec 을 한 줄만 고쳐도 전부 밀린다 — 실제로 16행 전량이 조용히 어긋나 있었고 아무도 몰랐다.
`make status` 와 같은 원리다: 읽는 시점에 만들면 충돌 0 이고 낡을 수가 없다.

```bash
make spec        # = python3 anchor.py --spec
```

## 절을 지목하는 법

컴포넌트 `CLAUDE.md` 헤더에 이렇게 적는다 — **파일 전체를 가리키지 않는다.**

```
> **읽을 절** spec **§3.1**(IF-1 계약) · **§2.3**(KG↔IAD 구분)
```

읽는 사람은 그 절만 연다. 지목이 없으면 **아무 절도 열지 않고** 컴포넌트 문서만으로 작업한다
(fail-closed). 절이 필요하다고 판단되면 그 컴포넌트 헤더에 지목을 **추가**하는 것이 먼저다.

## 고칠 때

설계 정본 수정은 **팀 합의 사항**이다. 먼저 `docs/decisions/CLAUDE.md` 절차로 결정 파일을 만들고,
`정본 반영`에 이 spec과 영향받는 `SOT.md`·`contracts/`·`interfaces/`·활성 `CLAUDE.md`·라우팅 문서를
적어 **같은 변경에서 함께 고친다.** 변경 전 핵심 용어·경로·ID를 `rg`로 전후 검색해 옛 지시가
활성 문서에 남지 않았는지 확인한다. 구조에 영향이 있으면 `SOT.md` §6도 필수다.
