# 결정 — 하나가 파일 하나

> **역할** 「그 밖의 결정」의 **정본.** 결정 하나 = 파일 하나 = 충돌 0
> **상태** 상시 · 신규는 전부 여기 · 이력 표는 `docs/decisions.md` 에 동결
> **읽을 절** 없음 — 읽을 일이 있으면 `make status` 가 최근 셋을 띄운다
> **정본** 구조 `SOT.md` · 설계 결정 `D-1`~`D-8` 은 spec §0.2 · 구조 결정 `D-9`~ 는 `SOT.md` §6

## 쓰는 법

파일 하나 만든다. **다른 파일은 건드리지 않는다** — 그래서 충돌이 없다.

```
docs/decisions/2026-08-09-kg-place-index.md      # YYYY-MM-DD-슬러그.md
```

```markdown
# 2026-08-09 · KG 장소 룩업을 인접 리스트로 둔다

> **정본 반영** `manager_ai_agent/knowledge_graph/CLAUDE.md`

왜 그렇게 했는지 한 단락. 되돌릴 사람이 읽는다고 생각하고 쓴다.
```

첫 `#` 줄이 `make status` 에 뜬다. 파일명 날짜로 정렬한다.

## 왜 표가 아닌가

표 맨 위에 한 줄을 넣는 방식은 **완전히 분리된 작업끼리도 충돌시켰다** — 실측에서
KG 담당과 MAC 담당이 서로 다른 컴포넌트만 건드렸는데 `decisions.md` 에서 충돌했다.
하네스 §4 가 **모든** 작업에 결정 한 줄을 요구하므로 모든 PR 이 그 파일을 지난다.

더 나쁜 것은 그 다음이다: **충돌 해소가 남의 줄을 떨어뜨려도 두 감사가 통과한다.**
충돌과 무관측이 겹치면 조용히 사라진다. `make status` 가 상태 수확에서 쓴 것과 같은
수법을 쓴다 — 한 사람이 한 파일만 만들고, 모으는 일은 읽는 시점에 한다.

**여기 파일은 부모 `CLAUDE.md` 에 등재하지 않는다.** 등재하게 만들면 그 등재 줄이
새로운 충돌 지점이 되어 원래 문제로 돌아간다 (`anchor.py` A8 도 이 디렉터리를 보지 않는다).

## 구조나 설계를 바꾼 결정이면

여기 파일을 쓰고 **정본에도 반영한다.** 반영하지 않으면 정본이 파생물보다 낡는다 —
실제로 그렇게 됐었다 (F-20). 정본이 어디인지는 `docs/doc-map.md` §3.
