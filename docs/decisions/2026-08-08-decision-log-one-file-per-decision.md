# 2026-08-08 · 결정 로그를 표에서 파일로 — 결정 하나가 파일 하나

> **정본 반영** `docs/decisions/CLAUDE.md` · `docs/harness.md` §4 · `docs/doc-map.md` §3 · `CONTRIBUTING.md` · `anchor.py` `decisions()`

표 맨 위에 한 줄을 넣는 방식은 **완전히 분리된 작업끼리도 충돌시켰다.** 2인 병합을 실제로
재현해 확인했다 — 협업자 A 가 `manager_ai_agent/knowledge_graph/`, B 가
`manager_ai_core/intent_extraction/` 만 건드렸는데도 `docs/decisions.md` 에서 충돌했다.
공유 파일이 그것 하나뿐이었다.

하네스 §4 가 **모든** 작업에 결정 한 줄을 요구하므로, 생태계가 모든 PR 에게
충돌이 보장된 파일을 지나가라고 지시하고 있었던 셈이다.

더 나쁜 것은 그 다음이다. **결정 행 하나를 지워도 `anchor.py --strict` 와 `sot_audit.py` 가
둘 다 통과한다** (실측). 충돌 해소는 사람이 손으로 하는 일이고, 급할 때 한쪽을 통째로
고르는 것이 가장 흔한 해소다. **충돌과 무관측이 겹치면 남의 결정이 조용히 사라진다.**

`make status` 가 상태 수확에서 이미 쓴 수법을 그대로 쓴다 — 한 사람이 한 파일만 만들고,
모으는 일은 읽는 시점에 한다. 충돌 0 이고 낡을 수가 없다.

기존 표는 **동결 이력**으로 남긴다. 옮기지 않는 이유는 아무도 과거 행을 편집하지 않아
충돌을 만들지 않고, 22행이 표로 있을 때 훑기 쉽기 때문이다.

**이 디렉터리의 파일은 부모 `CLAUDE.md` 에 등재하지 않는다.** 등재를 요구하면 그 등재
줄이 새 충돌 지점이 되어 원래 문제로 돌아간다.
