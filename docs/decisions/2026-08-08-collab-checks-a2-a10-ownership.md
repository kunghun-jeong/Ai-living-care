# 2026-08-08 · 협업이 만드는 세 실패를 관측한다 — A2 시그니처 · A10 채번 · 소유 경계 경고

> **정본 반영** `anchor.py` `A2`·`A10` · `.githooks/pre-commit` · `docs/harness/docs-and-structure.md` · `CONTRIBUTING.md` · `docs/doc-map.md` §3

협업자가 둘 이상이면 터지는데 아무도 안 보던 것 셋을 열었다. **전부 「알린다」·「말만 한다」로
커밋을 막지 않는다.**

**A2 를 시그니처까지.** `api-spec.md` 는 MCP 작업자의 유일한 계약서인데 A2 는 tool
**이름 집합**만 봤다. 파라미터를 더하거나 기본값을 바꿔도 문서는 조용히 낡았다. 이름
누락은 여전히 **막고**(그 tool 이 있는 줄도 모르게 된다), 파라미터 목록 불일치는
**알린다**(탐색 중 인자 변경은 정상이다). **반환 타입은 비교하지 않는다** —
`get_camera_snapshot` 처럼 코드에 애노테이션이 없는데 문서가 실제 거동(`list | dict`)을
적어 두는 편이 정확한 경우가 있고, 그건 갈라짐이 아니라 문서가 더 많이 아는 것이다.

**A10 — 같은 ID 를 두 번 정의하는 것.** 둘이 동시에 `F-70` 을 집으면 서로 다른 결함이
같은 번호를 갖고도 `--strict` 가 통과했다 (실측). 병합은 두 행을 나란히 남기므로 git 도
조용하다. 옛 `DA-5`(**없는 것을 가리킴**)의 반대 방향이고, 협업에서 실제로 터지는 것은
이쪽이다. `D-*` 는 보지 않는다 — spec §0.2 와 `SOT.md` §6 **양쪽 갱신**이 규범이다.

**소유 경계 경고.** 2026-08-06 에 경계를 넘어 8개 파일이 수정됐고 전부 되돌렸는데, 그때
있던 장치(옛 `DA-6`, 보존 blob 고정)는 폐기됐고 대체가 없었다. 담당자 미배정이라
`CODEOWNERS` 를 못 쓰고 `master` 는 직접 푸시라 리뷰도 못 막는다. **그래서 막지 않고
묻는다** — 담당자 본인이면 `OWNER=1`. 각 트리의 `CLAUDE.md` 는 우리 규범이라 예외다.
이건 `DA-6` 의 복원이 아니다. 넘는 것을 **막지는 못하고, 모르고 넘는 것만 줄인다.**
