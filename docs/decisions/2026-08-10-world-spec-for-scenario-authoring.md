# 2026-08-10 · 시나리오 저작용 세계 명세서 추가

## 무엇

`tools/limo-patrol-viz/WORLD.md` 를 새로 만들었다. 시나리오를 작성·실행하는 **LLM 이 읽는**
세계 명세서다. `small_house.world` 의 `<model>` 89개에서 뽑은 가구 실좌표, 구역별 로봇 접근점,
랜드마크별 관측점, 카메라 특성(3D 원본 vs 2D 근사), 시나리오 1 재현 절차, 도구 표면,
그리고 이 검증이 답하지 못하는 것들을 담았다.

`tools/limo-patrol-viz/CLAUDE.md` 에 앵커 한 줄을 넣고, "최초 커밋과 내용이 동일하다"는
문장이 낡으므로 코드 한정으로 범위를 좁혔다.

## 왜

사용자가 "할머니 괜찮은지 확인해 줘" 같은 요청을 하면, LLM 이 이 문서만 읽고 시나리오 1과
같은 시뮬레이션을 재현하고 새 시나리오를 이 세계 위에 올릴 수 있어야 한다. 그전에는
좌표가 어디서 왔는지가 대화 기록에만 있었고, LLM 이 "침실"을 좌표로 옮길 근거가 없었다.

기존 코드는 건드리지 않았다 (D-14·D-17).

## 문서를 만들며 실측으로 확인된 것

- **맵의 침실 구역이 67.5% 미탐색이다.** `map.pgm` 을 만든 SLAM 주행이 침실에 들어가지 않았다.
  침대·냉장고·옷장은 셀 자체가 미탐색이라 **관측점 계산이 불가능**했다. 침실을 목표로 하는
  시나리오는 2D 기하 검증을 건너뛰거나 맵을 다시 떠야 한다.
- **커버리지 93.6% 의 분모는 맵의 자유공간이다.** 미탐색 영역이 분모에 없으므로
  "집 전체의 93.6%" 가 아니다. 지금까지 이 구분 없이 인용해 왔다.
- **인물 사진 오브젝트가 20개** (벽 액자 10 + 탁상 액자 10). 하단 벽면 `y≈−5.4` 에 6개,
  식탁 북쪽 벽 `y=3.08` 에 3개가 나란히 걸려 있다. YOLO 오탐 위험 구간이 좌표로 특정됐다.
- `Scenarios/check_obj_state.json` 이 부르는 `look_around` · `is_looking_around` ·
  `interrupt_look_around` 는 MCP 서버가 노출하는 6개 도구에 없다. `layer` 로 Worker_functions
  를 직접 가리키는 것으로 보이나 **러너의 디스패치 방식은 TODO(확인 필요)**.

앞의 두 항목은 기존 수치의 해석을 바꾸므로 결과를 인용할 때 같이 적어야 한다.
