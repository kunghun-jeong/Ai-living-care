# 2026-08-08 · 안전 결함도 파일 하나씩 — 표는 절차만 남긴다 (D-18 갱신)

> **정본 반영** `docs/safety/CLAUDE.md` · `SOT.md` §6 `D-18` · `docs/status.md` · `docs/doc-map.md` §1·§3 · `anchor.py` `A5`·`--status` · `CLAUDE.md`

담당자 둘이 각각 결함을 올리면 `status.md` 안전 표가 충돌했다 (실측). 결정 로그와 같은
문제이고 같은 해법을 쓴다 — `docs/safety/F-NN-슬러그.md` 하나가 결함 하나다.
`anchor.py` A5 의 **양방향 강제는 그대로다**: 파일 ↔ 귀속 컴포넌트 `상태` 줄.

**`status.md` 에는 D-18 절차가 남는다.** 그 문서가 매 세션 자동 로딩되기 때문이다.
목록까지 거기 두면 결함이 늘 때마다 자동 로딩 예산이 늘고, **결함을 기록하는 일이 예산에
막히면 안 된다** — 2026-08-07 에 `status-defects.md` 를 분리한 것과 같은 이유다.

**존재 신호는 잃지 않는다.** 두 경로로 간다: `make status` **맨 위**(하네스 §0 이 세션
시작에 돌리게 한다)와, 귀속 컴포넌트 `CLAUDE.md` 의 `상태` 줄. 그 컴포넌트를 건드리는
사람은 하네스 §1 에 따라 그 문서를 먼저 읽는다 — **결함이 필요한 사람에게 닿는 경로는
원래 그쪽이었다.** 자동 로딩은 「모두에게 항상」이고, 이건 「그 사람에게 그때」다.
