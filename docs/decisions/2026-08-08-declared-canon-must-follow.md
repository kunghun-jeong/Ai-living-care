# 2026-08-08 · 결정이 선언한 정본이 같은 PR 에서 실제로 바뀌었는가 (CI 경고)

> **정본 반영** `.github/workflows/check.yml` · `docs/harness/docs-and-structure.md` · `CONTRIBUTING.md`

앵커는 **「추가」**를 잡는다 — 하위에 파일이 생기면 부모가 알게 된다. 그런데 **「방향 변경」은
하위에 아무 파일도 만들지 않아 갱신할 앵커가 없다.** 실측으로 갈라 봤다:

| | 결과 |
|---|---|
| 새 컴포넌트, 부모 등재 잊음 | 🔴 막힘 |
| spec 절을 **삭제** (10곳이 인용) | 🟡 알림 (A3) |
| spec 절 **내용**을 뒤집음 (L2 XML→JSON) | 🟢 **아무도 모름** |
| `SOT.md` `SP-4` 폐기 | 🟢 **아무도 모름** |
| 결정으로 방향 바꾸고 정본 미반영 | 🟢 **아무도 모름** |

이 저장소가 겪은 old-path 3건(`docs/CLAUDE.md` 읽는 순서 · 하네스 장치 표 7행 · `V-*`)이
전부 이 유형이고, **셋 다 그 시점에 하위 anchoring 은 완벽했고 감사는 초록이었다.**
하위 문서는 상위 규범을 197회 인용하는데 그 인용은 규범이 바뀔 때 따라오지 않는다.

**상위가 하위를 심사하는 장치가 아니다.** `> **정본 반영**` 은 작업자가 자기 손으로 쓰는
선언이고(형식에 이미 있어 새로 쓸 것이 0), CI 는 그 선언이 참인지만 본다 — A5(안전 결함
파일 ↔ `상태` 줄)와 **같은 구조**를 「결정 ↔ 정본」에 적용한 것이다.

**경고만 한다.** 그리고 **「선언 자체를 안 한 경우」는 못 잡는다** — 그건 기계가 아니라
규약의 몫이고, 거기서는 라우팅으로 충분하다 (`make status` 가 최근 결정을 띄우므로
검수자가 「이 PR 은 결정이 없네」를 본다).

부수로 훅의 `py_compile` 을 `compile()` 로 바꿨다. `py_compile` 은 `.pyc` 를 실제로 쓰는데
경로가 Windows MAX_PATH(260자)를 넘으면 실패하고 **「구문 오류」라는 틀린 이유로 커밋을
막는다** (266자에서 재현). 이 저장소는 175자로 여유가 85자뿐이다.
