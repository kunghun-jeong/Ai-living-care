# 작업 하네스 (Harness)

> **작업을 시작하기 전에 해당 하네스를 먼저 읽는다.** 하네스는 그 작업에 필요한 컨텍스트,
> 사전 점검, 검증 절차, 결정 기록 기준, 아키텍처 리스크 판정을 규정한다.
>
> 하네스는 "잘 하자"는 권고가 아니라 **통과해야 하는 관문**이다.

## 어떤 하네스를 읽나

| 하려는 일 | 하네스 |
|---|---|
| MCP tool 추가·수정, 서버 기동, A2A/IF-4 | @docs/harness/mcp.md |
| Perception · Reasoning · Action 수정, `limo-MCP/` 내부 | @docs/harness/worker-agent.md |
| Manager AI Core·Analyzer·MAMS·KG·IAD 신규 구현 | @docs/harness/manager-ai.md |
| Gazebo·Nav2 브링업, 순찰 도구, 맵·좌표 | @docs/harness/simulation.md |
| 문서·SOT·디렉터리 구조·스펙 | @docs/harness/docs-and-structure.md |

여러 개에 걸치면 **전부** 읽는다. 어디에도 안 걸리면 이 문서의 공통 절차만 따른다.

> **무엇을 고쳤을 때 어디를 함께 고쳐야 하는지**는 @docs/doc-map.md 에 있다 (4-2단계).

---

## 공통 절차 — 4단계

### 1단계 · 컨텍스트 로딩 (Lazy)

전부 읽지 않는다. 아래 순서로 **필요한 것만** 읽는다.

1. 루트 `CLAUDE.md` — 전체 그림과 현재 Phase
2. @docs/status.md — **지금 무엇이 깨져 있는지.** 건드릴 영역의 갭(G-*)·결함(F-*)을 먼저 확인
3. 해당 작업 하네스 (위 표)
4. 건드릴 디렉터리의 `CLAUDE.md` — 그 컴포넌트의 규범과 알려진 함정
5. 필요하면 @docs/architecture.md, @docs/api-spec.md, @docs/conventions.md

> **금지**: 설계 정본(`docs/spec/*.md`, 958줄)을 통째로 읽지 않는다. 하네스가 지목한 절만 읽는다.

### 2단계 · 사전 점검 (Pre-flight)

작업 대상이 **지금 정상 상태인지** 먼저 확인한다. 깨진 상태에서 시작하면 내 변경이 원인인지 알 수 없다.

```bash
# 공통 — 어떤 작업이든
git rev-parse --abbrev-ref HEAD                       # 브랜치 확인
test -d worker_ai_agent/limo-MCP || echo "FAIL: 구 레이아웃"
python3 sot_audit.py                                   # 구조 규범 (실행 가능성은 미보증)
python3 -m compileall -q $(git ls-files '*.py')        # 구문
for s in $(git ls-files '*.sh'); do bash -n "$s"; done # 셸 구문
```

작업별 추가 점검은 각 하네스에 있다. **하나라도 실패하면 거기서 멈추고 원인을 먼저 정리한다.**

### 3단계 · 검증 (Verify) — 통과 못 하면 커밋하지 않는다

**"동작할 것이다"는 검증이 아니다. 실행해서 확인한 것만 검증이다.**

모든 작업에 공통으로 적용되는 최소 기준:

| # | 기준 |
|---|---|
| V-1 | 변경한 코드 경로를 **실제로 한 번 실행**했다. 실행 명령과 출력을 커밋 메시지 또는 PR에 남긴다 |
| V-2 | **실패 경로도 실행**했다. 잘못된 입력·의존 서비스 부재 상태에서 무엇이 일어나는지 확인했다 |
| V-3 | 문서에 적은 명령을 **그대로 복사해 실행**해서 통과했다 |
| V-4 | 새로 만든 상태값·열거값·필드가 있으면 **그것을 읽는 모든 소비자**를 찾아 갱신했다 |
| V-5 | `python3 sot_audit.py` 통과 |

> **V-2가 이 저장소에서 가장 자주 빠진 항목이다.** 포렌식이 찾은 결함 대부분(F-1~F-6)이
> "정상 경로만 확인하고 실패 경로를 안 본" 결과다.

### 4단계 · 기록과 리스크 판정

#### 4-1. 의사결정 기록

아래 중 **하나라도 해당하면** @docs/decisions.md 맨 위에 기록한다. 판단이 애매하면 기록한다.

- 인터페이스(IF-*)의 계약을 정하거나 바꿨다
- 스키마(L1~L3, Report)를 정하거나 바꿨다
- 의존성을 추가·제거·고정했다
- 상태 열거값·에러 처리 방식을 바꿨다
- 디렉터리 구조나 파일 배치를 바꿨다
- 알려진 갭(G-*)·결함(F-*)을 해소했거나, 해소하지 않기로 했다
- 성능·안전 트레이드오프를 선택했다

```markdown
## YYYY-MM-DD: 결정 제목
- 변경: 무엇을 바꿨나
- 이유: 왜 바꿨나
- 참고: 관련 파일 / PR
```

구조·설계에 영향을 주는 결정은 **원문(`SOT.md` §6 또는 spec §0.2)에도 반영**한다.

#### 4-2. 전파 — 무엇을 함께 고쳐야 하나

**변경한 사실이 다른 문서에도 복제돼 있는지 확인하고 전부 갱신한다.**

→ **@docs/doc-map.md 의 §2 「변경 유형별 전파 체크리스트」에서 해당 행을 찾아 그 대상을 전부 갱신한다.**

자주 빠뜨리는 것:

| 바꾼 것 | 자주 빠뜨리는 대상 |
|---|---|
| 하위 컴포넌트 추가·삭제 | **부모 `CLAUDE.md`의 구성 표**, **`docs/architecture.md` 다이어그램 + 컴포넌트 표**, `sot_audit.py`의 `COMPONENTS`/`CHILDREN` |
| MCP tool 변경 | **`docs/api-spec.md`**, `Scenarios/*.json`의 tool 이름·인자, `architecture.md`의 데이터 흐름 |
| 상태 열거값 추가 | **그 값을 읽는 모든 소비자** (V-4). 판정 로직(MAA)까지 |
| 갭 해소 | `docs/status.md` 해당 행, 컴포넌트 `CLAUDE.md`의 ⚠️ |
| 구조 결정 | spec §0.2 **와** `SOT.md` §6 **양쪽** (한쪽만 하면 두 정본이 갈라진다 — D-14에서 실제 발생) |

**같은 사실을 새로 복제해야 한다면** @docs/doc-map.md §1에 정본을 선언하고 §4 중복 표에 행을 추가한다.
선언 없는 복제는 위반이다.

#### 4-3. 아키텍처 영향력 · 리스크 판정

변경이 **컴포넌트 경계를 넘는지** 판정한다.

| 등급 | 조건 | 필요 조치 |
|---|---|---|
| **R0 — 국소** | 한 컴포넌트 안, 인터페이스·스키마 불변 | 하네스 검증만 |
| **R1 — 인터페이스** | IF-* 계약, MCP tool 시그니처, 상태 열거값, 반환 스키마 변경 | **@docs/doc-map.md §2 전파 전부** + decisions.md 기록 + 양쪽 소비자 전수 확인 |
| **R2 — 구조** | 디렉터리 이동·신설, 컴포넌트 추가, 의존 방향 변경 | R1 조치 + `SOT.md` §2 트리 + `sot_audit.py` 검사 대상 + **`docs/architecture.md`** + `MIGRATION.md` |
| **R3 — 설계** | 정책 계층(L0~L4), 컴포넌트 책임, Phase 계획, 표준화 항목(S-*) 변경 | R2 조치 + **설계 정본(spec) 갱신** + 팀 합의 |
| **R4 — 안전** | 로봇 정지·취소 경로, 사람 검출·판정, 세션 키 검증 | R3 조치 + **실패 경로 실증 필수** + 리뷰어 2인 |

**R4 판정 기준 — 아래에 해당하면 무조건 R4다:**

- `cancel` / `stop` / e-stop 경로를 건드린다
- `status` 전이나 타임아웃을 건드린다
- 사람 검출 결과가 "정상/이상" 판정으로 이어지는 경로를 건드린다
- 프레임 신선도·증거 이미지 체인을 건드린다

> 이 프로젝트는 **독거 어르신 돌봄 로봇**이다. "조용히 잘못 보고하는 것"이 "요란하게 실패하는 것"보다
> 훨씬 위험하다. 의심스러우면 한 등급 올린다.

#### 4-4. 리스크를 남기기로 했다면

해소하지 않고 넘어가는 것은 **반드시 문서에 남긴다.** 침묵은 금지다.

- @docs/status.md 의 갭·결함 표에 행을 추가하고 ID를 부여한다
- 해당 컴포넌트의 `CLAUDE.md` 에 ⚠️ 항목으로 적는다
- 재현 조건과 영향을 구체적으로 쓴다 — "위험함"이 아니라 "카메라가 죽으면 옛 사진으로 정상 보고"

## 하네스가 막으려는 실패 (실제 사례)

| 사례 | 어느 단계가 막았어야 했나 |
|---|---|
| 루트 문서의 실행 명령 3줄이 전부 존재하지 않는 경로 | V-3 (문서 명령 그대로 실행) |
| 정수 좌표 하나로 시퀀스 스레드가 조용히 사망 | V-2 (실패 경로 실행) |
| Nav2 미기동 시 클라이언트 무한 루프 | V-2 + V-4 (상태 열거값 소비자 전수) |
| goal 수락 타임아웃 후 로봇이 멈추지 않음 | R4 (안전 등급 판정 + 실패 경로 실증) |
| `mcp` SDK 하한 없이 2.0 전용 API 사용 | 사전 점검 (의존성 버전 확인) |
| CLAUDE.md를 손으로 고쳤는데 생성기가 되돌림 | R2 (구조 변경 시 도구 정합성) |
| S-4/S-7 오귀속이 상위 문서에서 CLAUDE.md 3개로 전파 | 4-2 전파 (doc-map §1 정본 소유권) |
| 구조 결정 D-14가 `SOT.md`에만 있고 spec에 미반영 | 4-2 전파 (양쪽 동시 갱신) |
