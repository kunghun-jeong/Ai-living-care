# 작업 하네스

> **규칙은 하나다. 작업 전에는 그 자리의 컨텍스트만 읽고, 작업 후에는 앵커와 결정 로그를 갱신한다.**
>
> 관문도, 등급도, 감사도 없다. 아래 네 단계가 전부다.

## 0. 지금 무엇이 바뀌었는지 본다 — **세션 시작에 한 번**

```bash
make status                  # make 가 없으면: python anchor.py --status
```

한 화면에 셋이 같이 나온다 — 전 영역 `상태` 줄 · **최근 커밋과 결정** · 자동 로딩 실측.
**파일에 쓰지 않으므로 낡을 수 없다.** 자동 로딩되는 네 문서는 남이 컴포넌트에서 일해도
변하지 않는다 — 그래서 **여기가 갱신을 보는 유일한 창구다.** 건너뛰면 어제 상태로 일한다.

> `상태` 줄은 **사람이 적은 것**이고 최근 커밋은 **git 이 아는 사실**이다. 둘이 어긋나 보이면
> 그 디렉터리 `CLAUDE.md` 의 `상태` 줄이 낡은 것이다 — 건드리기 전에 확인한다.

## 1. 읽는다 — 필요한 것만

**무엇을 열지는 `docs/doc-map.md` §1 이 정한다.** 거기 없으면 이 문서만 따른다 (fail-closed).

1. 건드릴 디렉터리의 `CLAUDE.md` — 그 컴포넌트의 계약과 알려진 함정.
   **헤더가 지목한 spec 절만** 읽는다 — 통째로 열지 않는다.
2. 그 영역을 **처음 건드릴 때만** 아래 참고 노트 — 코드를 며칠 읽어야 알 수 있는 함정 모음
3. 그 외에는 읽지 않는다.

| 건드리는 것 | 참고 노트 |
|---|---|
| MCP tool · A2A / IF-4 | `docs/harness/mcp.md` |
| Perception · Reasoning · Action · `limo-MCP/` **코드** | ⛔ 담당 연구원 영역 — `docs/status.md` 에 결함만 기록 (D-17) |
| 〃 의 **규범**(`CLAUDE.md`) 또는 담당자 본인 | `docs/harness/worker-agent.md` |
| Manager 신규 구현 | `docs/harness/manager-ai.md` |
| Gazebo · Nav2 · 순찰 · 맵 | `docs/harness/simulation.md` |
| 문서 · 디렉터리 구조 | `docs/harness/docs-and-structure.md` |
| 매거진 논문 | 노트 없음 — `docs/doc-map.md` §2 팀장 문서 + spec §11 + `docs/status.md` 수치·한정어 |
| IITP 제안서 | 노트 없음 — spec §11.1(`S-*` 정본)까지만. **spec 은 제안서의 기준 문서가 아니다** |

## 3. 앵커를 갱신한다

**파일이나 디렉터리가 생기거나 이름이 바뀌면, 그 자리의 `CLAUDE.md`에 한 줄 넣는다.**
새 디렉터리를 만들었으면 거기에 `CLAUDE.md`를 만들고 **부모 `CLAUDE.md`에도 한 줄** 넣는다.

```bash
make hooks    # 최초 1회 — 이후 커밋할 때 자동으로 돈다
make check    # 손으로 확인하고 싶을 때 (PR 기준 --strict)
```

**상태가 바뀌었으면 그 `CLAUDE.md` 의 `상태` 줄도 같이 고친다** — 그게 §0 에서 남이 보는
줄이다. 코드만 고치고 `상태` 줄을 두면 `make status` 는 **옛 값을 자신 있게** 보여준다.
잊으면 훅이 커밋 때 한 줄 알려준다 (막지는 않는다).

훅을 설치했으면 **잊어도 커밋 시점에 걸린다.** 훅을 안 깔았거나 `SKIP_ANCHOR=1` 로 넘겼어도
PR 에서 CI 가 같은 검사를 한다 (`.github/workflows/check.yml`) — 그쪽이 병합 관문이다.

## 4. 결정 로그에 한 줄

`docs/decisions.md` 맨 위에 **한 줄**. 날짜 · 무엇을 · 왜.
스키마 · 인터페이스 계약 · 상태 열거값 · 의존성을 바꿨다면 그것만 한 줄 더 붙인다.

## 예외 — 안전에 닿는 변경

**로봇 정지·취소 / 사람 검출→판정 / 프레임 신선도 / 세션 키 검증** 넷 중 하나를 건드렸다면,
**실패 경로를 한 번 실행해 보고 그 결과를 결정 로그에 적는다.** 이것만이 유일한 추가 요구다.

> 독거 어르신 돌봄 로봇이다. **조용히 잘못 보고하는 것이 요란하게 실패하는 것보다 위험하다.**
> 지금 알려진 결함은 `docs/status.md` 에 있다 — 건드릴 영역에 해당 항목이 있는지만 확인한다.
